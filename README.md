# Tabstead（页栈）

一个本地优先、面向当前 Chrome 窗口的标签页侧边栏。

Tabstead 希望解决的不是“把横向标签搬到侧边”，而是让不断增长的标签页变得更容易整理、找回和复用：常用页面可以固定，长期工作流可以收进固定文件夹，临时页面则按网站自动聚合。

> 当前版本：`0.15.4` · Chrome 114+

## 核心能力

- 只管理当前 Chrome 窗口，不打扰其他窗口
- 顶部固定常用网站，并在浏览器重启后保留
- 用自定义固定文件夹保存长期工作页面
- 将同一主域名下的多个临时标签自动聚合展示
- 映射 Chrome 原生标签组，不擅自改变或删除原生结构
- 搜索、切换、关闭、静音、固定和拖动标签
- 再次打开相同网址时，自动复用当前窗口已有标签
- 手动复制标签时允许保留副本
- 清理重复标签，并支持撤销刚刚关闭的标签
- 固定页面站内跳转后，标题和网站图标实时跟随原生标签更新
- Chrome 140+ 可识别原生拆分视图：标签保留原分组，并显示当前焦点、同屏伙伴和跨分组定位
- 顶部永久固定图标在长列表滚动时保持吸顶
- 自动形成的网站临时分组支持悬停后一键关闭组内全部标签
- 支持跟随系统外观，也可在底部工具区手动选择浅色或深色主题

所有设置和固定入口只保存在浏览器本地。扩展没有后端服务，不上传浏览记录，也不包含第三方统计代码。

## 界面结构

侧边栏从上到下分为三个区域：

1. **固定图标**：适合每天都会访问的常用网站。
2. **固定空间**：用用户自定义文件夹组织长期工作流。
3. **临时标签**：呈现当前窗口正在使用的普通标签和网站集合。

数量、搜索、重复清理和帮助默认收纳在底部工具区，尽可能把空间留给标签内容。

## 安装体验版

### 使用源码

1. 下载或克隆本项目。
2. 在 Chrome 地址栏打开 `chrome://extensions`。
3. 开启右上角的“开发者模式”。
4. 点击“加载已解压的扩展程序”。
5. 选择本项目的 `src` 目录。
6. 将 Tabstead 固定到工具栏，点击图标打开侧边栏。

代码更新后，在扩展管理页点击“重新加载”。

### 使用发布包

从 GitHub Releases 下载 `Tabstead-v<版本号>.zip`，解压后按照上述步骤加载解压目录。正式发布包只包含扩展运行文件、图标、README 和 LICENSE。

## 常用操作

- 点击标签：切换到对应页面
- 右键普通标签：复制、加入固定文件夹、固定、静音或关闭
- 拖动普通标签到固定文件夹：保存为长期入口
- 在同一个固定文件夹内拖动条目：调整长期入口顺序
- 右键固定文件夹条目：打开、复制、永久固定、静音、关闭或移出文件夹
- 拖动页面到顶部：永久固定为图标
- 拖出固定区域：取消固定或恢复为临时标签
- 右键固定文件夹：在文件夹内新建标签、全部打开、重命名或删除
- `Command/Ctrl + K`：搜索当前窗口标签

## 权限说明

| 权限 | 用途 |
| --- | --- |
| `sidePanel` | 在 Chrome 原生侧边面板中显示界面 |
| `tabs` | 读取、切换、创建、关闭、移动和静音当前窗口标签 |
| `tabGroups` | 展示并操作 Chrome 原生标签组的安全子集 |
| `storage` | 保存固定入口、固定文件夹和会话绑定状态 |

扩展不申请网页内容访问权限，也不会读取网页正文、表单或账号密码。完整说明见 [PRIVACY.md](PRIVACY.md)。

## 数据与边界

- 固定入口和固定文件夹保存在扩展本地存储中。
- 标签标题、网址、图标和状态来自 Chrome Tabs API。
- 网站自动聚合只影响侧边栏展示，不会创建或打乱真实 Chrome 标签组。
- Chrome 原生标签组的关闭、删除、保存和跨设备同步仍由 Chrome 顶部标签栏管理。
- Chrome 暂未向普通 Side Panel 扩展开放浏览器主题的具体颜色，也没有扩展级左右位置或最小宽度控制 API。
- Chrome 目前只向扩展开放拆分视图状态读取，创建或退出原生拆分视图仍需通过顶部标签栏完成。

## 开发与校验

项目使用原生 HTML、CSS 和 JavaScript，不需要安装依赖或执行构建。

```bash
node --check src/background.js
node --check src/sidepanel.js
node --check src/theme-init.js
python3 -m json.tool src/manifest.json >/dev/null
```

生成可以直接加载和上传 Chrome Web Store 的 ZIP：

```bash
python3 scripts/package_extension.py
```

安装包会生成到 `dist/`，其中 `manifest.json` 位于 ZIP 根目录。`dist/` 是生成目录，不提交到 Git。

功能验证目前以 Chrome 中手动加载扩展为主。提交问题时，请附上 Chrome 版本、复现步骤和扩展错误页截图。

## 项目结构

```text
Tabstead/
├── src/                 # 可以直接加载的扩展源码
│   ├── manifest.json
│   ├── background.js
│   ├── sidepanel.html
│   ├── sidepanel.css
│   ├── sidepanel.js
│   ├── theme-init.js
│   └── icons/          # Chrome 扩展图标
├── docs/images/        # README 与 Release 展示图片
├── scripts/            # 校验和发布工具
├── .github/            # Actions 与 Issue 模板
├── README.md
└── LICENSE
```

`src/` 是扩展工程主目录，开发者克隆后可以直接在 Chrome 中加载。仓库根目录只保留项目文档、发布工具和 GitHub 配置；打包脚本会把 `src/` 中的运行文件重新放到 ZIP 根目录。
